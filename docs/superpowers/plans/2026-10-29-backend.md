# Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the Django + PostgreSQL REST backend for the supermarket app: auth and loyalty card, public offers/flyer/stores, shopping lists, and a staff management API.

**Architecture:** One Django project in `backend/` with five apps (`accounts`, `catalog`, `offers`, `stores`, `shopping`). Django REST Framework serves `/api/v1/`; `drf-spectacular` publishes the OpenAPI contract from which the Flutter client is generated. Tests run with pytest against Postgres.

**Tech Stack:** Python 3.12, Django 5.x, djangorestframework, djangorestframework-simplejwt (with blacklist), drf-spectacular, django-storages, Pillow, argon2-cffi, psycopg 3, pytest, pytest-django, factory_boy, ruff, mypy, Docker Compose, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-29-backend-design.md`

## Global Constraints

- Base path `/api/v1/`; JSON over HTTPS; schema at `/api/schema/`.
- Access token 15 min, refresh token 30 days, refresh rotation with blacklist.
- Roles: `customer` | `staff`. Staff are created or promoted only in Django admin, never via the API.
- Prices are `DecimalField`; one currency from settings. No floats for money.
- Error shape everywhere: `{"code": "...", "detail": "...", "fields": {...}}`.
- Cursor pagination on list endpoints.
- Image upload: JPEG, PNG or WebP only, max 5 MB, resized.
- Argon2 password hashing; stricter throttle on `/auth/*`; `DEBUG=False` in prod; secrets from env vars only.
- No PostGIS; store "nearest" sort is plain Python/SQL distance on lat/lng.
- Out of scope: push, payments, ordering, coupon redemption, social login, offline conflict resolution beyond last-write-wins.

## Review Focus

- Register with an already-used email (case-insensitive) must return a 400 field error, not a 500.
- A customer sending `role: "staff"` in register or `PATCH /me` must not change their role.
- A flyer with `valid_from` after `valid_to` must be rejected.
- Pagination with an empty table returns an empty page, not an error.
- `GET /stores` with only `lat` (no `lng`) or non-numeric coordinates returns a 400, not a 500.
- Uploading a renamed non-image file (e.g. `.png` containing text) is rejected.
